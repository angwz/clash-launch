# 0009 · 站内消息的端到端加密

- 状态：已采纳（2026-11-22，需求 R46）
- 范围：站内消息的文字部分。节点与授权附件、系统通知不在范围内；修订 [security](../design/security.md) 中「消息正文以主密钥加密保存」一条

## 背景

站内消息的正文原先只以服务器主密钥加密保存：数据库泄露时读不到，但服务器与能拿到主密钥的管理员可以解密。R46 要求文字部分做到服务器只见密文。浏览器的 Web Crypto 足以实现，不引入第三方库。

## 威胁模型

| 能防住 | 防不住 |
| --- | --- |
| 数据库或备份泄露（连同主密钥）后读消息 | 运行中的服务器被篡改：登录时服务器会收到密码，被改过的服务器可以截下密码再解开私钥 |
| 管理员查库、看日志 | 被改过的前端代码（与上一条同源：页面由服务器提供） |
| 服务器按正常代码运行时读到消息正文 | 对方设备上的消息（对方本来就能读） |

也就是说，这里的端到端加密保护的是**存下来的数据**与**照常运行的服务器**。私钥由登录密码派生的密钥包裹；真正对抗恶意服务器需要独立于登录密码的口令与可校验的客户端代码，代价是每台设备都要另记一个口令，本决定不采用。

## 决定

| # | 主题 | 决定 |
| ---: | --- | --- |
| 1 | 密钥 | 每个用户一对 ECDH P-256 密钥，在浏览器生成。公钥明文存服务器，任何登录用户可以读取；私钥只以包裹后的形式离开浏览器 |
| 2 | 包裹 | 包裹密钥 = PBKDF2-SHA256（登录密码、16 字节随机盐、600 000 次）→ AES-256-GCM。服务器保存 `{盐, 次数, IV, 密文}`。另可生成恢复密钥（32 字节随机数，以 Base32 显示一次），经 HKDF-SHA256 得到第二把包裹密钥，保存第二份包裹 |
| 3 | 设备上的私钥 | 解开后以**不可导出**的 `CryptoKey` 存在 IndexedDB，按用户区分；退出登录时删除。换设备或清了浏览器数据时，在消息窗口输入密码重新解锁 |
| 4 | 加密一条消息 | ECDH（自己的私钥，对方的公钥）→ HKDF-SHA256（信息串含双方的密钥编号）→ AES-256-GCM，每条消息随机 12 字节 IV。收发双方都能用同一共享密钥解密。没有前向保密（静态密钥），换取实现简单、多设备与历史消息可读 |
| 5 | 服务器的校验 | 加密消息的 `text` 必须为空；`enc` 中的密钥编号必须是发件人与收件人**当前**的密钥；IV 与密文长度有上限。服务器不解密，也不能搜索加密消息；会话列表的预览显示为「加密消息」 |
| 6 | 何时加密 | 双方都有密钥、且自己的私钥已在本机解锁时，文字自动加密。否则照旧以主密钥加密发送，发送框旁明确标出「未加密」及原因，不静默降级 |
| 7 | 生成密钥 | 用密码登录、注册或首次设置后，没有密钥就生成并上传；通行密钥登录时没有密码，打开消息时再输入密码解锁或生成 |
| 8 | 改密码 | 改密码时在浏览器内用旧密码解开、新密码重新包裹，与新密码同一请求提交，服务器在同一事务里更新 |
| 9 | 忘记密码 | 管理员重置或用安全问题找回后，旧包裹解不开：可以用恢复密钥解锁并以新密码重新包裹；没有恢复密钥时只能重新生成密钥，此前的加密消息无法再读。这一点写进用户协议（R40）与帮助 |
| 10 | 密钥历史 | 重新生成时旧公钥保留（标为不再使用），对方仍能解开你以前发给他的消息；旧私钥不在服务器上，不能恢复 |
| 11 | 注销账户 | 删除包裹后的私钥；公钥保留，对方仍能读以前的对话（与 R20 保留对话一致） |
| 12 | 不加密的部分 | 节点与授权附件（服务器要据此加入节点页、授权使用）、系统通知、消息的发送时间与收发双方。用户协议写明节点与配置本身不能端到端加密 |

## 后果

- 加密消息只有收发双方的浏览器能读；服务器不能代为搜索、预览或转发其中的文字。
- 忘记密码又没有恢复密钥时，此前的加密消息永久无法读取。恢复密钥在账号页生成并提示用户保存。
- 公钥对任何登录用户可见：只透露「此人启用了消息加密」，不透露其他信息。

## 依据

- Web Crypto API：ECDH、HKDF、PBKDF2、AES-GCM、`wrapKey` 与不可导出的 `CryptoKey`（W3C Web Cryptography API）
- PBKDF2-SHA256 的次数按 OWASP Password Storage Cheat Sheet 的建议（600 000）
