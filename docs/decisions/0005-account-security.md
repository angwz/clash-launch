# 0005 · 账号安全的具体选择

- 状态：已采纳（2026-11-10，M5）
- 范围：第 14.1 节在 M5 中的参数与取舍；威胁模型与逐项测试清单见 [security](../design/security.md)

## 参数

| 主题 | 决定 | 理由 |
| --- | --- | --- |
| 工作量证明 | SHA-256(挑战 ":" nonce) 的前导零位数 ≥ 20（`CLASH_LAUNCH_POW_BITS`）；挑战为 HMAC 签名的无状态载荷，5 分钟有效、只能使用一次；注册与找回需要 | 实测浏览器端（中间状态优化后）约 108 万次/秒，20 位平均 0.74 秒；挡住批量请求，不依赖第三方验证码 |
| 安全问题 | 3 个，内置问题只存编号（文字随界面语言）；答案 NFKC + 小写 + 合并空白后以 argon2id 存储；答对 2 个即可找回 | 规范第 14.1 节；规范化让「ＢＥＩＪＩＮＧ」与「beijing」相同 |
| 用户名探测 | 找回接口对不存在的用户名返回由密钥派生的稳定诱饵问题；不存在的用户同样做三次哈希 | 响应形状与耗时一致。自定义问题仍会暴露账号存在，这是用户选择自定义问题的代价 |
| 找回锁定 | 按账号连续失败 5 次、按 IP 连续失败 10 次后锁定 15 分钟；成功后注销该账号全部会话 | 规范第 14.1 节 |
| 登录退避 | 按账号：前 3 次不等待，之后 1 s 起翻倍，最长 15 分钟；按 IP：前 10 次不等待 | 同一出口下有多个用户；退避期内不再校验口令，避免被用来测时 |
| 两步验证 | TOTP（RFC 6238，SHA-1、30 秒、6 位，容许 ±1 步），同一时间步只能用一次；10 个一次性恢复码（只存 SHA-256） | 认证器应用普遍只支持 SHA-1；RFC 附录 B 向量在测试中核对 |
| 第二步凭证 | 口令正确后签发 5 分钟有效的签名凭证，不建立会话；第二步失败计入登录退避 | 无状态；重启后需要重新输入口令 |
| 新设备 | 「IP 前缀（IPv4 /24、IPv6 /48）+ 浏览器族」首次出现时提醒；注册后一分钟内的登录不提醒 | 不依赖地理库；粒度粗，宁可多提醒 |

## 通行密钥

- **自行实现服务端验证**（`internal/auth/webauthn.go`），不引入 go-webauthn：与 mihomo 固定的 `golang.org/x/*` 兼容的版本是 2024 年的 v0.11.2，更新的版本会抬高 `x/crypto` 等依赖（见 [0001](0001-deviations-from-spec-1.0.md) #17）。实现范围刻意收窄：只接受 `attestation: "none"`（收到其他格式时忽略来源证明），算法 ES256、EdDSA、RS256，要求用户在场与用户验证，签名计数不得回退。CBOR 使用依赖树中已有的 `fxamacker/cbor`。
- **验证**：软件认证器的单元测试覆盖规范 §7.1、§7.2 的每一项检查（挑战、来源、类型、RP ID、UP/UV、签名、计数）；端到端测试用 Chromium 的虚拟认证器走真实的浏览器流程。
- **挑战只能使用一次**：同步型通行密钥（iCloud 钥匙串、Google 密码管理器）的签名计数始终为 0，不能靠计数发现重放。
- **角色**：可作为免密码登录（视为已完成两步验证），启用了 TOTP 时也可以在第二步代替验证码；但不会让口令登录额外要求通行密钥——否则丢失设备且没有恢复码时会被锁在门外。
- **依赖方**由 `CLASH_LAUNCH_PUBLIC_URL` 决定（RP ID 为主机名）；未配置时通行密钥不可用，界面说明原因。
- 删除通行密钥需要口令。

## 未验证

- 真实的手机与硬件安全密钥（iOS、Android、YubiKey）未测试；只验证了软件认证器与 Chromium 虚拟认证器。
- 工作量证明在手机浏览器上的耗时未实测。
