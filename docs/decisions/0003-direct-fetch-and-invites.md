# 0003 · 去掉出站代理；注册开关与一次性邀请

- 状态：已采纳（2026-11-09，M3 之后）
- 范围：替代规范第 14.6 节（出站代理与 WARP 边车）、第 18.3 节（WARP compose），以及 [0001](0001-deviations-from-spec-1.0.md) #16、[0002](0002-storage-and-service.md#部署第-18-节) 中的 WARP 部分；补充第 14.1 节的注册方式

## 背景

出站代理（默认 WARP 边车）是为了不让订阅提供方看到服务器 IP。它带来的成本不小：多一个容器与官方客户端的运行条件、出口不可用时整体停止拉取、「交给客户端 / 管理员直连」等按角色区分的获取方式，以及一层只为它存在的配置与界面说明。与之相比，控制「谁能使用这台服务器」更直接：服务器 IP 只会暴露给能在这里添加订阅的人所对应的提供方，而这些人由管理员决定。

## 决定

| # | 主题 | 决定 |
| ---: | --- | --- |
| 1 | 拉取 | 服务器直接连接目标，不再有出站代理、`CLASH_LAUNCH_EGRESS_*`、`CLASH_LAUNCH_ALLOW_USER_DIRECT`、源的 `allowDirect` 与 `fetch` 字段、快照的 `via`。SSRF 防护不变，并且因为直连，`net.Dialer.Control` 对每次连接的实际地址都生效（见 [network](../design/network.md)） |
| 2 | 部署 | 单容器；删除 `deploy/warp/` 与 `compose.minimal.yaml`，`compose.yaml` 只含本服务 |
| 3 | 注册开关 | 管理员设置 `registration.open`，**默认关闭**；保存在 `settings` 表，修改写入审计日志 |
| 4 | 一次性邀请 | 注册关闭时，管理员生成邀请链接 `<对外地址>/register#<令牌>`，有效期可选（小时，0 = 不过期，最长 90 天），可附备注。令牌 24 字节随机数，库中只存 SHA-256，原文只在创建时返回一次；放在 URL 片段中，不进入反向代理的访问日志 |
| 5 | 使用邀请 | 注册时以一条带条件的 `UPDATE`（未使用且未过期）消费邀请，与创建用户在同一事务中：用户名冲突等失败会连同邀请的消费一起回滚，并发的两次注册只有一次成功。注册开放时忽略邀请参数 |
| 6 | 管理接口 | `/api/v1/admin/registration`、`/api/v1/admin/invites`；非管理员一律 404，不暴露接口存在。邀请可撤销（删除）；列表显示 `active`、`used`、`expired` 状态，不再返回链接 |
| 7 | 注册接口 | `GET /api/v1/register` 返回是否开放；`POST` 创建普通用户：用户名 3–32 个字符、不含空白与控制字符、不区分大小写唯一；口令规则与管理员相同；同源检查；每 IP 每小时 10 次 |

## 后果

- 订阅提供方能看到服务器的出口 IP。部署文档写明这一点；需要隐藏 IP 的管理员可以在宿主机或网络层自行处理（例如让整台服务器经过代理出网），本项目不内置。
- 获得注册资格的用户可以通过添加一个自己控制的订阅地址得知服务器 IP；这是邀请制下由管理员承担的信任前提。
- M5 中的 PoW、安全问题等反滥用措施只作用于开放注册；邀请注册不需要。
