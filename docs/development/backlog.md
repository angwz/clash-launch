# 需求清单

维护者提出、尚未完成的需求，以及做完后仍值得改进的地方。每项记录现状核实、工作量与优先级，供维护者按额度挑选，供接手的代理直接开工。

- 意见的来历记在 [feedback](feedback.md)，这里只记要做的事；完成后移入「已完成」并写明落点，细节进 [progress](progress.md)。
- 「现状」写核实过的事实（读过代码或实际运行），推测另行标注。
- 编号 `R` 连续、不复用；拆分时加后缀（R2a）。代理提出、尚未确认的建议用 `N` 编号，确认后改编为 `R`。

**工作量**按代理的 token 用量粗估，单位是一个对话的上下文窗口（读代码、改动、测试与同步文档都计入）：XS 不到 1/10 · S 约 1/4 · M 约半个到一个 · L 一个以上，需先出方案、分批做。这是经验估计，实际随要读的代码量与测试失败次数浮动；占每周额度的比例取决于订阅档位，以 claude.ai 的用量页为准。
**优先级** P1 缺陷或影响已有功能 · P2 明确想要 · P3 可以等
**状态** 🕓 待办 · 🔄 进行中 · ❓ 待维护者决定 · ✅ 已完成 · ➖ 不做

## 方案草案

开工前的设计要点；实施时整理进 `docs/design/`，这里只留链接。

### R10 足迹

**原则**：只记不会重复、日后回看有意义的事。同一类事件每人最多记一次，或在跨过阈值时记一次。永久保存，不受审计保留期影响，随账号导出，随账号删除。

**记哪些**：

| 类别 | 事件 |
| --- | --- |
| 起点 | 注册（加入日期与邀请人）、第一次登录、第一次启用两步验证或通行密钥 |
| 搭建 | 第一个节点源、第一个配置、第一次通过 mihomo 检查、第一次开始自己管理分流、第一条期望 |
| 启用 | 订阅第一次被客户端拉取（最有仪式感的一刻）、每种客户端第一次出现（如第一次用 Clash Verge 拉取） |
| 累计 | 订阅被拉取 100 / 1 000 / 10 000 / 100 000 次；配置连续在用 30 / 100 / 365 天（按每天是否被拉取） |
| 轨迹 | 订阅第一次从某个国家或地区被拉取、第一次从某个新地区登录（依赖 R7）；用户名与昵称的历次变更（也用于防冒充，依赖 R4、R5） |
| 社交 | 第一个好友、第一条消息、第一次授权给别人、第一次收到授权 |
| 站点（管理员） | 网站第一天上线、第一位注册用户、用户数 10 / 100 / 1 000 |

周年（加入一周年等）由注册日期推算，不单独存。

**存储**：新表，每行包含用户、事件类别、键（如国家代码、阈值）、发生时间与少量附加信息；（用户, 类别, 键）唯一，重复写入自动忽略，因此在各处触发点直接写入即可，不需要先查。上线时从已有数据补记能推算出的事件（注册时间、第一个配置的创建时间、统计里最早的拉取日），并标明「补记」。

**呈现**：账户页新增「足迹」时间线；达成时弹出一次轻提示，指示灯同时播放一次庆祝效果（见 R11）。

### R11 在线指示灯

**外观**：直径约 8 px 的圆点，颜色取主题强调色。外圈一层柔光，深色主题下更明显，浅色主题下收敛。断线时灯芯变暗、只留一圈细边框，仍能看出这里有元素。

**状态**：多个状态同时成立时，取优先级最高的。

| 优先级 | 状态 | 触发 | 表现 |
| :---: | --- | --- | --- |
| 1 | 断线 | 心跳连续两次失败（避免网络抖动造成误熄） | 熄灭；按退避间隔重试，恢复时双闪一次 |
| 2 | 新版本 | 服务器版本号与页面加载时不同 | 换成第二种颜色常亮，说明里提示「刷新即可使用新版本」 |
| 3 | 降级 | 往返延迟持续偏高，或服务端的内核检查不可用 | 琥珀色常亮，说明里写明原因 |
| 4 | 未读消息 | 有未读 | 呼吸：约 5 秒一个周期的明暗渐变，类似笔记本合盖后的呼吸灯 |
| 5 | 一次性事件 | 进入页面；订阅被拉取；保存或检查完成、失败；达成足迹（R10） | 进入时连闪三下后渐亮，呼应「启动」；被拉取时快闪两下；完成时一闪确认，失败时闪一下警示色；达成足迹时光晕向外扩散一圈 |
| 6 | 工作中 | 自动保存或 mihomo 检查进行中 | 轻微脉动 |
| 7 | 操作中 | 移动、点击、拖动、滚动，或分流地图的粒子正在流动 | 亮度随操作起伏，停止约 1.5 秒后回落 |
| 8 | 静止 | 以上都不成立 | 常亮 |

**夜间**：按用户时区，深夜时整体更暗，呼吸更慢。它叠加在上述状态之上，不单独占一个优先级。

**交互**：灯本身不能点击，不接收点击动作。桌面端悬停或用键盘聚焦时显示说明；手机上轻点后显示约 3 秒自动消失。说明内容：当前状态、在线人数、与服务器的往返延迟、最近一次订阅被拉取的时间、未读数。管理员可以设置不向普通用户显示在线人数。

**数据**：走 R22 的 WebSocket 通道：在线人数、未读数、订阅被拉取、新版本等都以事件推送，「被拉取时快闪」因此是秒级。连接断开时退回轮询一个轻量接口（如 `GET /api/v1/pulse`，返回同样的数据，每 15 秒一次，标签页隐藏时暂停）。在线人数按最近 5 分钟有活动的会话去重计数，服务端缓存 10 秒。

**无障碍与性能**：
- 闪烁每秒不超过 3 次（WCAG 2.3.1 的闪光阈值）。
- 系统开启「减少动态效果」时只保留常亮与熄灭两种状态，账户设置里也可以关闭动效。
- 动画只改变 `opacity` 与 `transform`，交给合成线程，不触发重排；标签页隐藏时停止。
- 不只靠颜色表达状态：断线时形状也变（空心），说明文字写明状态。读屏软件只播报断线与恢复。

**分步交付**：先做外观、断线、启动、常亮、操作与说明（M），再加未读、被拉取、工作中、新版本与降级，最后接足迹与夜间。

### R13 节点可用性检测

**本机检测**：服务器为要检测的节点生成一份最小的 mihomo 配置（不开入站端口，控制接口只监听本机回环地址并设密钥），启动 mihomo 后，经控制接口的延迟测试逐个检测，完成后退出。这样各种协议（含 UDP 类的 hysteria2、tuic）都由与客户端相同的内核实现，结论最接近真实使用；单纯连一下端口的 TCP 检测对 UDP 协议无效，也测不出密码错误。

**测试地址不用第三方**：默认请求本服务自己的一个返回 204 的地址，用户也可以自行指定。回程顺带带回「节点的出口 IP」，再经本地地理库得出实际出口地区，能发现「名字写着香港、实际从日本出去」的节点，与地区识别（[nodes](../design/nodes.md)）互相印证。

**必须处理的风险**：
- **SSRF**：节点地址由订阅提供，可能指向内网；mihomo 自行解析域名，绕过了现有的 SSRF 防护。检测前要解析并拒绝内网地址，检测时让 mihomo 使用固定的解析结果，防止 DNS 重绑定。
- **频率**：每人限定检测频率与并发，避免服务器被当作扫描器，也避免节点提供方因频繁探测封禁服务器。
- **出站边界**：这会新增「连接节点服务器」这类出站连接，需要先写一份决定记录，修订[网络边界](../design/network.md)。

**agent**：服务器的网络位置往往和用户的不同（比如服务器在海外、用户在国内），只在服务器上测，「能用」不等于在家里能用。agent 解决的就是这个问题：
- 在用户的账户页生成 agent 链接，内含一次性令牌，在其他机器上安装 agent 时用它换取长期凭据；之后可在页面上随时吊销。
- agent 只主动向服务器发起 HTTPS 连接、取任务、交结果，不开端口，家用宽带和 NAT 后面都能用。
- 节点信息含密码，只发给节点所有者自己的 agent；给 agent 起名（家里宽带、公司、东京 VPS），结果按「节点 × 检测位置」成表。
- 每台 agent 附带官方原版的 mihomo，检测方式与本机检测相同。

**不开源的做法**（以下是对许可证的理解，不构成法律意见；正式发布前建议咨询律师）：
- 本项目是 GPL-3.0，并且编译时链接了 mihomo（同为 GPL-3.0）。所以服务器程序只要对外分发（包括公开的 Docker 镜像），就必须提供源码，**检测功能放在服务器程序里就无法闭源**。
- 你是自己代码的版权人，可以另写一个独立程序，用其他许可证发布，前提是它不包含他人的 GPL 代码（mihomo、本仓库里别人贡献的代码）。
- 闭源程序**调用**原版 mihomo 可执行文件，经它的控制接口通信，一般视为两个独立程序的「聚合」，不会让闭源部分沾上 GPL；但随程序分发的 mihomo 本身仍要附上许可证，并提供对应版本的源码获取方式。
- 因此可行的结构是：开源的服务器只定义一套「检测器」接口；闭源的检测器（服务器侧组件与 agent 是同一个程序）在私有仓库里开发，以二进制发布；开源版没有检测器时，这部分功能不显示。
- 代价：闭源程序会接触到用户节点的密码，用户只能选择信任；闭源二进制也能被逆向，真正的保护在于它离不开账户与服务器。

**待决定**：是否接受新增的出站连接类型；闭源组件的仓库与发布方式（属于远端操作，到时另行确认）。

### R14 PostgreSQL 与千万级数据

**结论先行**：生产部署改为默认 PostgreSQL；SQLite 保留给本机开发、单元测试与很小的私人部署，不再作为推荐的生产选项。完全移除 SQLite 会让 `go test ./...` 离不开数据库服务，离线测试与每次改表结构写两份迁移的成本得不偿失，所以建议保留。如果你希望彻底只留 PostgreSQL，这是唯一需要拍板的点。

**会增长到千万级的表**：`sub_requests`（每次订阅拉取一行，目前从不清理）、`audit`（保留 180 天）、`messages`、`sub_ips`。其余表随用户数线性增长，量很小。

**分批**：

| 批 | 内容 | 用量 |
| --- | --- | :---: |
| R14a 部署 | 提供 PostgreSQL 版的 compose（在 R18 的最简文件之上叠加，`docker compose -f compose.yaml -f compose.postgres.yaml up -d`），部署与搬迁文档改为以它为主；连接池上限、语句超时、空闲连接可配置；备份改为 `pg_dump` 说明（应用内的备份命令保留） | S |
| R14b 基准 | 造千万行的测试数据（只用文档地址与虚构账号），对每条热点查询记录 `EXPLAIN ANALYZE` 与耗时；之后每项优化都以实测数字为准 | M |
| R14c 订阅明细 | 分析改为在数据库里按天、国家、客户端、小时聚合，不再把明细读进内存（去掉 5 万行截断）；明细设保留期（如 90 天），更早的只留按天汇总；PostgreSQL 上按月分区，清理旧数据直接删分区，不做大批量 `DELETE`；写入改为多行批量插入 | L |
| R14d 分页与日志 | 审计、用户列表、消息改为键集分页（按「时间 + ID」翻页，不再 `OFFSET`）；总数改为估算或只在第一页计算；审计按月分区；为未读数、会话列表补齐复合索引 | M |
| R14e 搜索 | PostgreSQL 上为用户名与昵称建 `pg_trgm` 索引，使「昵称中任一段」的搜索走索引；SQLite 维持现状（数据量小） | S |

**约束**：迁移仍按约定两种数据库各一个同号文件；PostgreSQL 专用的分区与索引只写在它的文件里，SQLite 的同号文件写等价的普通结构或留空说明。分区改造涉及已有表的数据搬移，上线前需在真实数据的副本上演练，并给出回滚步骤。

### R17 配置导入导出

**导出**（M）：在配置页「导出」下载一份客户端能直接用的 YAML，与订阅链接下发的内容同源（同一渲染、同一 `mihomo -t` 检查）。
- 选项：含节点 / 不含节点（`proxies` 与 `proxy-providers` 留空，策略组改指向占位，导出后由用户自行填入）；含规则集 / 不含规则集（`rule-providers` 与引用它们的规则一并去掉，只留手写规则与兜底）。去掉的内容逐项进入导出说明，不静默删除。
- 目标客户端：沿用客户端预设（mihomo、OpenClash，之后的 Clash Verge Rev、Stash 见 R15、R16），同一份配置按所选客户端适配；不支持的客户端不出现在选项里。
- 不含节点、不含规则集的导出可作为分享给别人的「骨架」，与模板（反馈 #51）互补：模板留在站内，导出带走。

**导入**（L）：粘贴网上复制的完整 Clash/mihomo 配置，反向解析为一个新配置。
- 节点 → 新建一个手动节点源（`proxies`）；`proxy-providers` → 订阅节点源（地址经 SSRF 防护，与手动添加相同）。
- 策略组、规则、`rule-providers` → 配置的 routing 段（分流可视化可以直接编辑）；能识别为已知规则集预设（如 domainrouter_v2、ACL4SSR）的标为来源，便于之后跟随上游。
- 其余字段按字段目录逐项归入表单层；目录里有但当前客户端不支持的、目录里没有的未知键，列为「无用内容」。
- 导入前给出预览：将要创建什么（节点数、策略组、规则数、表单字段），以及每一条无用内容与原因（未知字段、与目标客户端不兼容、被内核忽略、外部控制与面板等运行期设置、明显的占位或示例值）。用户确认后才写入，无用内容丢弃；也可以选择把未知字段放进原始编辑层原样保留。
- 用户写下的内容原样保留：节点名、组名、正则、手写规则不改写，看起来不规范只提示。
- 只接受 YAML；订阅链接、Base64 节点列表与 subconverter 的 ini 已有入口（节点源、外部配置），在导入页给出指引。

**风险**：网上的配置常含失效字段与过时写法，反向解析的覆盖面决定体验，需用一批真实样本（只取公开发布的配置，不入库原文中的凭据）做回归。

### R18 最简 docker compose

**目标**：默认的 `compose.yaml` 只留启动必需的三样，复制即可运行：

```yaml
services:
  clash-launch:
    image: ghcr.io/angwz/clash-launch:latest
    ports: ["20230:20230"]
    volumes: ["./data:/data"]
```

另给一行 `docker run` 的等价写法，供不用 compose 的人。

**为此要改镜像，而不是让用户在 compose 里补参数**：
- **数据目录权限**：镜像默认以 root 启动，由程序把 `/data` 交给运行用户后立即降权（现在靠 compose 的 `user: "0:0"` 实现）。这样数据卷、宿主机目录、NAS 共享目录都不用手动改权限。另支持 `PUID`、`PGID` 环境变量，供群晖、威联通、Unraid 等需要指定宿主机用户的系统使用。
- **重启策略**：compose 无法由镜像决定，最简文件里保留 `restart: unless-stopped` 一行（不写的话机器重启后服务不会自动起来），这是三样之外唯一建议保留的。
- **加固项**（只读根文件系统、去掉 Linux 能力、禁止提权）移到 `compose.hardened.yaml`，用 `-f` 叠加；文档说明它们的作用与为什么默认不开（部分 NAS 与 rootless 环境不支持）。

**要实测的环境**：Linux（Docker 与 Podman，含 rootless）、Windows 与 macOS 的 Docker Desktop、群晖 Container Manager、Unraid；amd64 与 arm64（树莓派 4/5）。armv7 目前没有镜像，是否补上看需求。

**与其他需求的关系**：PostgreSQL 版（R14a）与加固项都以叠加文件提供，不让默认文件变长；对外地址与反代网段这类按需配置只写在部署文档里。

### R19 头像与默认昵称

- **上传头像**：PNG、JPEG 或 WebP（上限 2 MB），服务器裁成正方形、缩到 256 px 并重新编码，去掉可能含拍摄地点的 EXIF。存在数据库里，由本站地址提供，不用 Gravatar 等第三方服务。解码 WebP 需要 `golang.org/x/image`，引入前确认不会抬高 `golang.org/x/*` 的版本，不行就只支持 PNG 与 JPEG。
- **预置头像**：一套与网站风格一致的 SVG 头像，主题取自「启动」：火箭、行星、彗星、卫星、星座、发射台等，每个图形配几种主题色，共约 60 个。原创绘制，不使用任何现有作品的角色或图案。深浅主题下都清晰，体积小、随前端打包。
- **预置昵称**：中英文各一套「形容词 + 名词」词表，同样取自启动与星空的意象，如「疾行的彗星」「Swift Comet」，各约 40 × 40 种组合。昵称不唯一，旁边总显示 @用户名。
- **随机分配**：注册时为新用户随机选一个预置头像和一个预置昵称，按注册时的界面语言选中文或英文词表，并写入账号，之后不再变化。已有用户在上线时补分配一次。用户可以随时换成别的预置头像、上传自己的，或改昵称；账户页提供「换一个」，从预置里重新抽。
- 头像显示在顶栏、消息、好友联想、邀请来的人与管理页。

### R20 注销账户

- 在账户页发起，需要当前密码（启用了两步验证时还要验证码）。先提示「导出我的数据」（R21）。
- 设 7 天冷静期：期间登录即可撤销；到期后删除全部数据，订阅链接与短链接立即失效。所有会话在发起时注销。
- 对别人的影响沿用 R2：给别人的授权收回并通知对方。对方的对话保留，显示为「已注销的用户」；邀请关系显示快照中的用户名。用户名按改名规则保留 180 天，防止被冒用。
- 管理员也可以注销普通用户，不需要冷静期，记入审计。最后一个管理员不能注销自己。

### R21 个人全部信息的备份与还原

- **备份**：账户页「备份我的全部信息」下载一个文件，内含账号资料（昵称、头像、偏好、时区）、节点源（含订阅地址与请求头）、配置与修订历史、模板、规则源、订阅链接与短链接（含令牌）、登录设备之外的全部设置。文件用备份时输入的密码加密：里面有节点凭据，而服务器的主密钥不随文件走。
- **还原即整体覆盖**：选择备份文件、输入备份密码与当前账号密码后，先显示将被替换的内容（现有多少节点源、配置、链接等，备份里有多少），确认后把当前账号的上述内容全部替换为备份中的内容。
- **还原前自动留底**：覆盖前先为当前状态自动做一次备份，保存 7 天，可以一键撤销这次还原。
- **订阅不断**：订阅链接与短链接按备份中的令牌恢复，客户端里的订阅继续可用。在另一台服务器上还原时，若令牌或自定义短码已被别人占用，换新的并在结果里列出。
- **对别人的影响**：还原后不再存在的节点源与短链接，原有授权按 R2 收回并通知对方。消息、好友与别人给你的授权属于双方共有，不在备份内，还原也不改动它们。
- 用户名、密码、两步验证与通行密钥不随备份覆盖，避免还原后登录方式意外改变。

### R22 实时更新（WebSocket）

- **选型**：WebSocket。单向通知用 SSE 就够，但正在输入、在线状态、即时已读这类效果需要浏览器也频繁、低延迟地向服务器报告，双向通道更合适。
- **效果**：
  - 消息：对方正在输入、已读回执即时出现、新消息带动画进入；
  - 在线状态：头像上的状态点，指示灯（R11）的在线人数实时变化；
  - 订阅分析的「实时请求流」：客户端拉取订阅时，列表顶端即时出现一条，计数随之滚动；
  - 配置重新生成、检查结果、授权变化、会话被注销或定时退出、新版本上线：就地更新，不用刷新。
- **连接管理**：同一浏览器的多个标签页共用一条连接（经 `BroadcastChannel` 在标签页之间转发），状态各页同步。心跳检测断线，按退避间隔重连；重连失败时退回现在的轮询。按用户限制连接数。
- **安全**：沿用会话 Cookie 认证；握手时校验 Origin（与写请求相同，含多域名白名单 R9），防止跨站借用登录状态建立连接（CSWSH）。服务器只推送当前用户有权看到的事件。
- **实现**：服务器用进程内的事件中心分发；多实例部署时改用 PostgreSQL 的 `LISTEN/NOTIFY`（与 R14 相关）。Go 标准库没有 WebSocket 服务端，倾向使用无依赖的 `coder/websocket`，引入前按约定确认不会抬高 `golang.org/x/*` 的版本。
- **部署**：Nginx 需要转发升级请求（`proxy_http_version 1.1` 与 `Upgrade`、`Connection` 两个头），并放宽读超时；Caddy 默认可用。写进 [reverse-proxy](../guide/reverse-proxy.md)。

### R40 用户协议

- **注册时同意**：注册页增加「我已阅读并同意《用户协议》」，未勾选不能注册；协议在单独页面打开（`/terms`，未登录也能访问），注册页内也可以展开阅读。
- **内容结构**：
  1. **设计理念**：本站做什么、不做什么。生成的配置严格按官方文档与源码实现，查不到就列为限制、不猜；运行时不调用任何第三方服务，出站连接只有你配置的订阅与规则源；你写下的节点名、组名、规则原样保留，看起来不规范也只提示；被跳过或改写的内容都会告诉你，不静默丢弃；数据随时可以带走（R21）。
  2. **我们保存什么**：服务器需要读取节点与配置的明文才能生成配置并经订阅链接下发，因此它们只能加密保存、不能端到端加密（站内文字消息可以，见 R46）；账号资料、节点与配置（凭据加密保存）、登录设备的 IP 网段与所在地（不保存完整地址）、订阅拉取统计；各自的保留期。与帮助中的「隐私与安全」相互链接，同一事实只在一处详述。
  3. **你的责任**：遵守所在地法律法规；不得用本站从事违法活动；对自己添加的节点与订阅内容负责；不分享他人的订阅链接与凭据。
  4. **服务说明**：站点由管理员自行部署与维护，不保证持续可用；可能因维护或违规而停用账号；协议更新时会提示重新同意。
- **管理员可改**：默认文本随程序提供（中英文）；管理员可在管理页编辑或替换，每次修改生成新版本号。
- **记录同意**：用户表记录同意的版本与时间（迁移）。协议有新版本时，已有用户下次登录先看到更新内容并重新同意，才能继续使用；拒绝则可以选择退出或注销（R20）。同意与拒绝都记入审计。
- **措辞与法律**：默认文本只陈述本站事实与使用规则，不写无法兑现的承诺。它不构成法律意见；面向公众开放注册的站点，管理员应按所在地要求自行审阅。
