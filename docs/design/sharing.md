# 分享与分析：订阅分析、短链接、导入到客户端、站内消息

四个功能都围绕「把配置交到别人或别的设备手里，并且知道它被怎样使用」。数据只属于所有者，按 [security](security.md) 的所有者隔离规则保存。

## 订阅分析

入口是左侧菜单的「订阅分析」，地址形如 `/analytics?days=&link=&short=`，筛选条件写在地址里，可以分享或从短链接页跳转。

| 内容 | 来源与算法 |
| --- | --- |
| 归属地与运营商 | 记录请求时用本机地理数据（`internal/geo`）查出国家代码与 ASN，存入 `sub_requests`，以后不随数据更新而改变。数据与内核检查共用 `CLASH_LAUNCH_GEODATA` 目录：`geoip.metadb` 提供国家，`ASN.mmdb` 提供运营商。读取方式与 mihomo 相同（`maxminddb-golang` v1.12.0），不访问外部服务；没有数据时只是不记录归属地 |
| 每天、星期 × 小时 | 按用户在设置里选的时区分桶；没有设置时用浏览器时区。区间结束于该时区的明天零点，每根柱子都是完整的一天 |
| 拉取间隔 | 同一 IP 相邻两次成功请求的间隔取中位数，忽略 10 秒内的重复请求（重试或并发） |
| 新出现的 IP | 在统计区间内第一次出现、且在最近 24 小时内的 IP；区间不足一天时不判断 |
| 规模上限 | 一次最多分析 50,000 条请求（`service.AnalyticsMaxRows`），超过时只分析最新的部分并在页面上注明 |

计算是纯函数 `service.Analyze`（`TestAnalyze`）。页面可见时每分钟自动刷新。

## 短链接

`/u/<短码>` 直接返回所指配置链接的内容，与 `/s/<令牌>` 完全相同，包括 `?download=1` 导出。

- **不重定向。** 原链接不会出现在客户端里；短链接停用后，用它的客户端立刻失效，不影响原链接。
- **短码**：随机短码 8 位，字符表去掉了容易混淆的 0、o、1、l、i，约 40 比特；自定义短码为小写字母、数字和连字符，3–32 个字符。全站唯一，不区分大小写。
- **只能指向自己的配置链接。** 存储层在同一事务里先核对链接归属再写入；删除配置链接时，指向它的短链接一并删除。
- **数量**：与配置链接共用同一个配额上限。
- **防猜测**：同一 IP 一小时内猜错 30 次后，`/u/` 对它返回 429。
- **统计**：请求同时计入原链接（`sub`）与短链接（`short`，键为短链接 ID），`sub_requests.short_id` 记录经由哪个短链接。

## 导入到客户端

配置链接与短链接旁的「导入」菜单，列出仍在维护的 mihomo 内核客户端的一键导入链接，并提供「导出」下载配置文件。

| 客户端 | 链接 | 依据 |
| --- | --- | --- |
| Clash Verge Rev | `clash://install-config?url=…&name=…` | 官方文档 URL Schemes |
| Mihomo Party | `clash://install-config?url=…` | 安装包注册 `clash` 与 `mihomo` 协议 |
| FlClash | `flclash://install-config?url=…` | README：`clash://`、`clashmeta://`、`flclash://` 等价 |
| Clash Meta for Android | `clashmeta://install-config?url=…` | README |

订阅地址与名称都做 URI 编码。列表在 [`web/src/lib/clients.ts`](../../web/src/lib/clients.ts)，新增客户端时先找到它文档中的写法。OpenClash 等没有导入链接的客户端，用复制地址或导出文件。

## 站内消息

| 方面 | 做法 |
| --- | --- |
| 内容 | 文字最多 2000 个字符，emoji 按普通 Unicode 字符处理。附件是自己节点页中的一项：手动节点附原文，订阅附地址、User-Agent 与间隔，**不附请求头**（可能含凭据） |
| 保存 | 正文与附件一起加密保存在 `messages.body_enc`（与其他密文相同的 AAD 绑定）。双方各自「删除」只是对自己隐藏 |
| 送达与自动加入 | 收件人默认开启「收到的节点自动加入节点页」：附件立即加入，名称后注明「（来自 用户名）」。加入后不会用于任何配置，直到收件人自己选用。配额不足或关闭自动加入时，消息照常送达，附件可以稍后在消息里手动加入（只加入一次） |
| 不接收与屏蔽 | 偏好 `inbox: off` 表示不接收，`blocked` 是屏蔽的用户 ID。收件人不存在、不接收、屏蔽了发件人，三种情况统一返回 404，不能借此判断对方的设置 |
| 频率 | 每个账号每小时最多发 60 条，管理员不限 |
| 刷新 | 侧栏的未读角标每分钟刷新；打开的会话每 15 秒刷新，会话列表每 30 秒刷新，页面不可见时暂停（`web/src/lib/live.ts`） |

## 验证

- 存储层：`TestSocialRepos`。覆盖不能指向别人的链接、短码不区分大小写、停用与过期、随链接级联删除，以及消息的可见性、隐藏、未读与只有收件人能加入。
- 接口：`TestShortLinksAnalyticsMessages`，覆盖完整流程；`TestOwnerIsolationAllRoutes` 覆盖新增的全部路由。
- 前端：e2e 覆盖生成短链接、访问计入统计、导入菜单、分析页图表；以及发送文字、emoji 和附件，对方的角标、自动加入与已读。
- 地理数据：`TestLookup` 用本机数据检查国家与 ASN 能读出；没有本机数据时跳过。
