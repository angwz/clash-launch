## 12. HTTP API

### 12.1 约定

- 所有管理接口在 `/api/v1/` 下，JSON 编码。契约以 `api/openapi.yaml`（OpenAPI 3.1）为准，前端的 TypeScript 类型从它生成；CI 检查实现与契约一致。
- 错误统一使用 RFC 9457 `application/problem+json`，`type` 字段取诊断代码，前端据此显示本地化消息。
- 可修改的资源都返回 `ETag`；修改时**必须**带 `If-Match`，版本不一致时返回 `412`，前端提示「已在别处修改」并提供对比。不做自动合并。
- 列表接口使用游标分页。
- 认证：会话 Cookie（浏览器）或 `Authorization: Bearer <个人 API 令牌>`（自动化）。两者权限相同，API 令牌可限制作用域。

### 12.2 资源

| 资源 | 路径 | 说明 |
| --- | --- | --- |
| 会话 | `/api/v1/session` | 登录、登出、第二因素验证 |
| 注册与找回 | `/api/v1/register`、`/api/v1/recovery` | 工作量证明挑战、注册、按安全问题找回 |
| 当前用户 | `/api/v1/me` | 资料、语言、时区、API 令牌；`…/security` 安全问题、通行密钥、TOTP、SMTP 提醒（含测试发送）；`…/sessions` 登录设备与注销；`…/audit` 个人审计记录 |
| 节点源 | `/api/v1/sources` | 增删改；`POST …/{id}/refresh` 立即拉取；`GET …/{id}/nodes` 解析结果与跳过清单 |
| 规则源 | `/api/v1/rule-sources` | 同上；`GET …/{id}/groups` 策略组与节点匹配预览 |
| 方案 | `/api/v1/profiles` | 增删改；`GET …/{id}/revisions` 版本历史；`POST …/{id}/rollback` |
| 预览 | `POST /api/v1/profiles/{id}/preview` | 用请求体中的草稿渲染并校验，不保存；返回 YAML、诊断与相对当前版本的差异 |
| 导入导出 | `/api/v1/profiles/import`、`…/{id}/export` | 方案文档、Clash YAML、Verge Merge、Stash 覆写 |
| 订阅链接 | `/api/v1/profiles/{id}/links` | 查看、新建、重置、删除、最近访问 |
| 目录 | `/api/v1/catalog/{pack}` | 目录元数据、JSON Schema、预设；可被浏览器长期缓存 |
| 管理 | `/api/v1/admin/…` | 用户、注册模式、配额、审计日志、系统状态 |
| 健康 | `/healthz`、`/readyz` | 无需认证；不泄露版本以外的信息 |

预览接口是编辑体验的核心：前端在用户停止输入 400 ms 后调用，所以渲染与校验**必须**足够快（目标与实测值写进 `docs/design/performance.md`，只写实测值）。

## 13. 订阅输出

### 13.1 端点

| 端点 | 内容 |
| --- | --- |
| `GET /s/<token>` | 方案的最新成功渲染结果，`text/yaml; charset=utf-8` |
| `GET /p/<token>/<source>` | `provider` 模式下托管的节点文件（第 5.6 节） |
| `GET /r/<token>/<name>` | 可选的「托管清洗」规则列表（第 6.5 节） |

响应头：

- `Content-Disposition: attachment; filename*=UTF-8''<方案名>.yaml`
- `profile-update-interval: <小时>`（方案设置，默认 12）
- `subscription-userinfo`：方案可选择「不输出」「取某个源」「汇总所有源」（流量相加，过期时间取最早）
- `profile-web-page-url`：可选，指向本服务的方案页
- `ETag` 与 `Cache-Control: private, no-cache`；支持 `If-None-Match` 返回 `304`

### 13.2 链接与令牌

链接是**永久有效**的：客户端随时刷新，拿到的都是最新的配置。

- 形式：`https://<对外地址>/s/<令牌>`。令牌为 256 位随机值，base64url 编码（43 个字符）；链接较长没有关系，不为缩短而降低随机性（维护者另有短链接服务）。
- **网页上随时可以查看与复制**，并显示二维码。令牌加密存储（与节点凭据相同的方式，第 14.4 节），另存一份 SHA-256 哈希用于请求时的查找，查找使用常数时间比较。
- **重置链接**：一键生成新令牌，旧链接立即失效；界面提示需要在客户端更新链接。
- 一个方案可以有多条链接（例如每台设备一条），每条有备注、创建时间、最近访问时间、最近访问的客户端 UA，可单独重置或删除。
- 令牌只出现在路径中，**不**写入访问日志；日志只记前 6 个字符。

### 13.3 失败与缓存

- 订阅请求只读缓存，不触发拉取或渲染。尚无成功结果时返回 `503` 与一段 YAML 注释说明，而不是空配置，以免客户端用空配置覆盖旧配置。
- 每个令牌按 IP 与令牌限流（默认每分钟 30 次）；超限返回 `429` 并带 `Retry-After`。

## 14. 多用户与安全

### 14.1 账号

服务面向公网，部署在 nginx 反向代理之后。注册与找回**从简**：维护者评估过，最坏情况是某个账号的节点泄露，可以接受；因此不要求邮箱，不做复杂的身份验证，但服务自身仍按公网服务的标准防护（14.2–14.5），不依赖 nginx 兜底。

- **角色**：`admin`、`user`。首个管理员由 `clash-launch admin create` 命令或首次启动时的一次性设置链接创建（链接打印在日志中，15 分钟有效）；**不存在默认密码**。
- **注册**：用户名 + 密码 + 3 个安全问题（从内置问题列表中选，也可自定义问题）。注册模式由管理员设定：开放（默认）/ 邀请码 / 关闭。为挡住机器人批量注册，注册与找回页面使用**本地的工作量证明验证**（浏览器计算一个小难题，约 1 秒；不依赖任何第三方验证码服务）。
- **找回**：输入用户名并回答安全问题，至少答对 2 题即可重设密码。答案在比较前做规范化（去首尾空白、统一大小写与全半角、Unicode NFKC），以 argon2id 哈希存储，与密码同等对待；找回尝试按账号与 IP 限速，连续失败后锁定 15 分钟。找回成功后，该账号的全部会话失效。
- **密码**：argon2id（参数写进决定，按 OWASP 当前建议）；最短 10 位，不限制字符类别；拒绝最常见的弱密码（随程序发布一份常见密码表，不联网查询）。登录失败按账号与 IP 指数退避。
- **可选的加强**（用户自己决定是否启用）：
  - **通行密钥（Passkey / WebAuthn）**：可作为免密码登录，或作为第二因素；
  - **TOTP** 两步验证与一次性恢复码；
  - **个人 SMTP 邮箱提醒**：用户填写自己的 SMTP 服务器与收件地址，发送测试邮件确认可用后启用。出现异常登录（新设备或新地区首次登录、密码或安全问题被修改、通过找回重设密码、通行密钥或两步验证变更）时发邮件提醒。SMTP 密码加密存储，只用于该用户本人的提醒。
- **会话管理**：用户可以看到当前所有登录的设备（UA、IP 前缀、最近活动时间），并逐个注销；修改密码时可选择「注销其他设备」。
- **管理员**可以重置他人密码、停用账号、调整配额，但**不能**查看他人的节点凭据、订阅 URL、链接或方案内容。

### 14.2 会话与 Web 安全

- 会话 Cookie：`HttpOnly`、`Secure`（HTTPS 下）、`SameSite=Lax`、`__Host-` 前缀；登录后轮换会话 ID；空闲与绝对过期时间均可配置。
- CSRF：所有写操作要求同源的 `X-CSRF-Token`（双提交令牌），并检查 `Origin`。
- 安全响应头：严格 CSP（`default-src 'self'`，无内联脚本、无 `unsafe-eval`）、`frame-ancestors 'none'`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`、HTTPS 下的 HSTS。
- 所有静态资源随二进制发布；**不**访问任何第三方 CDN、字体或统计服务。
- 反向代理：可配置受信任代理网段，只从受信任代理读取 `X-Forwarded-For`/`X-Forwarded-Proto`；未配置时忽略这些请求头，限流与登录记录使用直连地址。`CLASH_LAUNCH_PUBLIC_URL` 设置后，生成的链接与 Cookie 的 `Secure` 属性都以它为准。
- 服务自身设置读写超时、请求头与请求体大小上限，防止慢速连接攻击；即使 nginx 配置有疏漏，服务也不会被单个连接拖垮。

### 14.3 数据隔离

- 所有用户数据表都有 `owner_id`；仓储层的每个查询函数都以用户上下文为第一个参数，**不**提供绕过所有者的查询（管理接口使用单独的、只返回元数据的函数）。
- **必须**有测试：用户 A 的每个资源 ID，用户 B 访问时得到 `404`（而不是 `403`，以免泄露资源存在）。

### 14.4 加密

- 节点原文、订阅 URL、订阅请求头、订阅链接令牌、TOTP 密钥、SMTP 密码用 AES-256-GCM 加密存储；每条记录带密钥 ID，支持在线轮换（`clash-launch keys rotate`）。
- 主密钥来源依次为：`CLASH_LAUNCH_MASTER_KEY`、`CLASH_LAUNCH_MASTER_KEY_FILE`、`/data/master.key`。三者都不存在时，首次启动生成 `/data/master.key`（权限 0600），并在日志与管理页醒目提示：**备份数据时必须同时备份密钥，丢失密钥就无法解密**。
- 日志与诊断中凭据、令牌、订阅 URL 的查询串一律脱敏。

### 14.5 不受信任的输入

| 风险 | 措施 |
| --- | --- |
| SSRF（订阅、规则源 URL、用户填写的 SMTP 服务器） | URL 只允许 `http`/`https`，SMTP 只允许 25、465、587 端口；DNS 解析后拒绝回环、私网、链路本地、CGNAT、组播、保留地址（IPv4 与 IPv6）；每次重定向后重新检查；在建立连接的 `Dialer.Control` 中检查实际连接的地址，防 DNS rebinding；管理员可设白名单 |
| 资源耗尽 | 响应体上限（默认 10 MiB）、超时（默认 30 s）、重定向上限（5 次）；每用户并发拉取数与拉取频率配额 |
| YAML 炸弹 | 解析前限制文档体积，解析中限制节点总数与别名展开次数 |
| 正则灾难性回溯 | `regexp2` 支持回溯，必须设置 `MatchTimeout`（默认 100 ms），超时记为诊断，而不是卡住整个渲染 |
| XSS | 用户内容只以文本渲染；YAML 预览与差异视图不解释 HTML；CSP 兜底 |
| 上传 | 体积上限；只按内容识别，不信任扩展名与 `Content-Type` |
| 内核检查 | 在临时目录中以无网络、限时、限内存的方式运行（第 11.3 节） |

### 14.6 出站隐私：不暴露服务器的真实 IP

服务器每次拉取订阅、规则源或连接用户填写的 SMTP 服务器，对方都能看到服务器的出口 IP。多用户场景下这是真实风险：任何注册用户都可以填一个自己控制的地址，从访问日志里拿到服务器的真实 IP，绕过 CDN 与反向代理的隐藏。本项目按以下方式处理（**必须**）：

1. **出站代理，默认使用 Cloudflare WARP**：所有出站连接（订阅、规则源、SMTP，以及任何运行时联网）统一走一个出口，由 `CLASH_LAUNCH_EGRESS_PROXY` 配置（`socks5h://` 或 `http://`）。
   - 默认的 `compose.yaml` 带一个 WARP 边车容器，以 SOCKS5 形式提供出口，`CLASH_LAUNCH_EGRESS_PROXY` 默认指向它；对方看到的是 Cloudflare 的 IP。
   - 边车只作用于本服务：它不改宿主机与其他容器的路由，只有本服务主动交给它的连接才经过它。
   - 边车镜像优先使用 Cloudflare 官方客户端的代理模式；不得不用第三方镜像时，固定到摘要（digest）并在决定中写明来源与理由（**待环境核验**：官方客户端在容器中的可行性、免费版当前的条款与限制）。
   - 也可以改成一台单独的小 VPS 或其他代理，只需修改这一个变量。
   - **出口不可用时不回退直连**：拉取失败，沿用上次成功的快照（第 5.4 节），管理页显示出口故障。宁可暂时拿不到新节点，也不暴露真实 IP。
   - 部分机场会拦截来自 Cloudflare 或数据中心的请求；可以为单个源设置「允许直连」，仅管理员可设，界面提示风险。
2. **没有配置出站代理时，默认只有管理员可以让服务器拉取**；普通用户的订阅只能选「交给客户端」模式（第 5.6 节），由客户端自己拉取，服务器不接触对方地址；SMTP 提醒对普通用户不可用。管理员可以在设置中明确改为「允许所有人直连拉取」，界面提示这会暴露服务器 IP。
3. **不泄露身份信息**：出站请求不带 `Referer`、`X-Forwarded-*`、Cookie 等多余请求头；UA 只用用户为该源设置的值或默认的 `clash.meta`，不附带本项目名称、版本与对外地址。
4. **配合 SSRF 防护**：使用 `socks5h` 出口时域名由代理解析，服务器无法在连接前检查解析结果；此时仍检查 URL 中的字面 IP，并拒绝 `localhost` 等主机名。私网地址相对于出口代理而言已不属于本机网络，风险随之转移到出口一侧，文档中说明这一点。
5. **添加订阅时如实告知出口**：添加或编辑订阅、规则源 URL、SMTP 设置的表单中，地址输入框下方**必须**显示一行出口说明，随实际配置变化：
   - 出口为 WARP：「服务器将通过 Cloudflare WARP 获取此订阅，订阅提供方看到的是 Cloudflare 的 IP，而不是本服务器的 IP。」
   - 出口为其他代理：「服务器将通过管理员配置的出站代理获取此订阅。」
   - 该源允许直连（仅管理员）：以警告色显示「此订阅由服务器直接获取，订阅提供方可以看到本服务器的 IP。」
   - 普通用户在没有出口时：不提供「写入配置」选项，并说明「此服务器未配置出站代理，订阅将由你的客户端自行获取」。
   - 出口当前故障：显示故障提示与最近一次成功拉取的时间。
   源列表中，每个订阅旁有一个小图标标明它的获取方式（WARP / 代理 / 直连 / 客户端获取），悬停显示同样的说明。
6. **管理页显示出口状态**：当前是否配置出站代理、出口 IP（通过一次自检请求获得，**默认**关闭，管理员手动触发），以及哪些用户的源正在由服务器拉取。

订阅端点本身（客户端访问 `/s/…`）只经过 nginx 与 CDN，不涉及这个问题。

### 14.7 审计与配额

- 审计日志：登录（成功/失败）、密码、安全问题、通行密钥与 TOTP 变更、账号找回、链接重置、方案修改、管理操作；保留期可配置。用户可以查看与自己有关的记录。
- 配额（每用户，管理员可调）：节点源数、方案数、订阅链接数、最短拉取间隔、存储体积。

威胁模型、各项默认值与理由**必须**写进 `docs/design/security.md`，并附一份逐项可验证的安全测试清单（M5 验收用）。

## 15. 多语言

### 15.1 范围：先打好结构，译文逐步完善

1.0 **必须**做到：

- 界面、诊断消息、字段说明全部走消息键，不在代码中写死任何界面文字；
- `zh-CN` 与 `en` 完整，由人工撰写；
- 布局能直接支持 RTL（第 15.3 节），以后加入波斯语、阿拉伯语时不需要改界面代码；
- 语言协商：用户设置 → `Accept-Language` → `en`。

以后再完善（**可选**，不阻塞 1.0）：更多语言、机器翻译流水线、社区校对平台。

### 15.2 机器翻译（以后再做）

**运行时不调用任何翻译服务。** Google 翻译 2022 年起在中国大陆不可用，Google Cloud 服务在伊朗受美国制裁限制；运行时调用会恰好在最需要照顾的地区失效。因此翻译在构建时完成，随版本发布：

1. 消息使用 ICU MessageFormat；`en` 是翻译的源语言。
2. `tools/i18n-sync` 在 CI 中调用 Google Cloud Translation，只翻译新增或源文变化的消息；占位符、字段名、代码片段包进 `<span translate="no">` 保护，返回后校验占位符完整；术语表保护 DNS、TUN、fake-ip、mihomo 等术语。没有 API 密钥时跳过，不影响构建。
3. 每条译文记录 `machine`/`reviewed` 状态与源文哈希；人工校对过的译文不会被机器翻译覆盖。社区校对可接入 Weblate（**待环境核验**免费托管条件）。
4. 语言选择器显示每种语言的完成度与「机器翻译」标记。

优先考虑的语言：`zh-TW`、`fa`、`ru`、`ja`、`ko`、`ar`、`tr`、`vi`、`id`、`es`、`pt-BR`、`fr`、`de`、`uk`、`my`。

### 15.3 RTL 与书写系统

- RTL 语言设置 `<html dir="rtl">`；所有样式使用 CSS 逻辑属性（`margin-inline-start` 等），**不得**出现 `left`/`right` 硬编码；有方向含义的图标随方向镜像。1.0 用一个伪 RTL 测试语言在端到端测试中检查布局。
- **配置值永远是 LTR 与 ASCII 数字**：端口、地址、YAML 编辑器、路径输入框固定 `dir="ltr"`；`Intl` 只用于显示日期、流量与计数。
- 字体：使用系统字体栈，不加载任何外部字体服务（Google Fonts 在中国大陆不可用）。

### 15.4 低带宽

首屏 JavaScript 预算（gzip 后）**默认** 150 KiB，在 CI 中检查；语言包、目录分节、CodeMirror 都按需加载；静态资源带内容哈希并长期缓存。实测值写进 performance 文档。

## 16. Web 界面

### 16.1 信息架构

```text
┌ 顶栏：方案切换 · 检查状态 · 命令面板 · 语言 · 用户 ─────────────────────────────────┐
```

### 16.2 字段卡片

选定客户端后，展示它支持的**全部**字段。每个分节内按重要程度分组：`core` 与 `recommended` 默认展开，`optional` 与 `expert` 默认折叠在「更多」中；分节顶部可切换「只看已设置」。

一张卡片包含：

- 标题与一句话摘要（当前语言）；展开后显示详细说明、相关字段的链接；
- 控件（按类型）与默认值（灰显）；
- 示例：点击即填入；
- 徽章：重要程度、`实验`、`已弃用`、`since` 版本（高于所选内核时为警告色）、`由客户端接管`、`⚡ 来自原始编辑`；
- 官方文档链接、「恢复默认」。

### 16.3 命令面板

`Ctrl/⌘ + K` 打开命令面板：搜索字段（跨分节，含摘要与详细说明全文）、跳转页面、切换主题与语言。

### 16.4 后备隐藏能源

原始编辑器就是后备隐藏能源，语义见[第 9.2 节](02-engine-and-catalog.md#92-原始编辑层后备隐藏能源)。

- **入口**：界面上没有按钮或标签页。只有两处入口：命令面板中输入 `>` 进入命令模式后才会出现的 `原始编辑`（英文 `raw edit`）；分节标题 `⋯` 菜单中的同名项，进入后编辑器定位到该分节。首次进入时显示一次说明。
- **编辑器**：主区切换为 CodeMirror 6（YAML 模式），右侧预览不变；基于 JSON Schema 补全、悬浮说明、实时报错；合并标签（`!append` 等）有补全与说明。
- **状态提示**：方案中存在原始编辑内容时，顶栏检查状态旁显示一个小小的 ⚡，点击直接进入；没有内容时，什么都不显示。

### 16.5 视觉与交互

- 气质：克制、精致、信息密度高；参考现代开发者工具的视觉语言，不堆砌装饰。设计 token（颜色、间距、圆角、字号）集中定义，浅色与深色主题都由 token 生成，跟随系统并可手动切换。
- 动效只用于状态变化（保存、校验结果、面板展开），尊重 `prefers-reduced-motion`。
- 可访问性：WCAG 2.2 AA 对比度；全部操作可用键盘完成；焦点可见；表单控件有关联标签；诊断同时使用颜色与图标表达。
- 响应式：宽 ≥ 1280 px 三栏；768–1279 px 预览栏改为抽屉；< 768 px 单栏。
- 改动视觉风格时，先给出真实数据的截图交维护者确认（与 domainrouter_v2 的约定相同）。

### 16.6 前端工程

- Svelte 5 + TypeScript（strict）+ Vite；CodeMirror 6；路由与状态管理选轻量方案，写进决定。
- API 客户端从 OpenAPI 生成；不在前端重写任何配置语义：合并、校验、渲染都通过预览接口由后端完成，前端只做即时的格式检查（JSON Schema）。
- 测试：Vitest（组件与工具函数）；Playwright 端到端（桌面、手机视口、伪 RTL、深色主题），后端使用真实二进制与临时数据目录。
