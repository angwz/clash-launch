# ノード：サブスクリプションと手動ノード

「ノード」ページはノードのライブラリです。各項目は**サブスクリプション**か**手動ノード**のどちらかです。

## サブスクリプション

提供元のURLを入力すると、サーバーが定期的に取得します。形式は自動で判別します：

- 1行に1つの共有リンク（`ss://`、`vmess://`、`vless://`、`trojan://`など）
- base64でエンコードされたサブスクリプション
- Clash / mihomoのYAML
- sing-boxのJSON
- WireGuardの設定ファイル（`[Interface]`と`[Peer]`を含む`.conf`）

取得に失敗すると、いつから失敗しているかがページに表示され、設定は最後に成功した取得結果を使い続け、チェック結果にもその旨が表示されます。

## 手動ノード

1つ以上の共有リンク、YAML、JSONを貼り付けます。自分のVPSや試しているノードに便利です。

## 整理

ソースごとにノード名を整理できます：国旗の付加や置き換え、正規表現によるノードの残す・除外、名前の変更と接頭辞、情報項目（残り通信量、期限）や重複の除去。地域は国旗とキーワードから判別します。判別が違う場合はノードの詳細で上書きしてください。

## 設定で使う

エディターの**ノードとルーティング**でソースを追加します。上から下がノードの順番で、ドラッグで並べ替えられます。各サブスクリプションの書き込み方は次の2つです：

- **設定に書き込む**：ノードは`proxies`に入るため、整理、名前の変更、プロキシチェーンがすべて適用されます。
- **クライアントに任せる**：`proxy-providers`として書き込み、クライアントが取得します。設定は小さくなりますが、クライアントが表現できない整理は飛ばされます（チェック結果に一覧表示されます）。

選び方：名前の変更、国旗の付加、地域ごとのグループ分け、チェーンをしたいなら設定に書き込みます。非常に大きい・頻繁に更新されるサブスクリプションや、クライアントからの取得しか許さない提供元なら、クライアントに任せます。迷ったら設定に書き込んでください。

新しく追加したサブスクリプションは、管理者が選んだ既定の方式を使います。管理者と招待されたユーザーはソースごとに変更できます。公開登録のアカウントは常に既定の方式を使い、チェック結果にもそう表示されます。
