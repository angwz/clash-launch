# 分流

「分流」页把配置里的规则和策略组画成一张图：一个请求从左边进来，经过哪条规则、交给哪个策略组，最后从哪个出口出去。在配置编辑器左侧点「分流」打开。

不熟悉这些概念时，先点标题旁的 **?**，五步讲清一次请求是怎么走的。

## 看懂地图

- **规则**从上往下比对，第一条认出请求的规则生效。相邻且走向相同的规则集会折叠成一行，点一下展开。domainrouter_v2 这样同名的 domain、ipcidr、classical 三个文件是一个**合集**，在图上占一行。
- **策略组**按「平时默认走的路径」分层：每个组没有手动选过时用第一个成员，所以连线总是从左往右。只当备选的成员平时不画，悬停或选中这个组、或打开「显示全部候选」时才出现。
- **出口**是节点、直连或拦截。节点多时按地区或来源归并成一行。
- 小圆点是示意，不是你的真实流量：每个圆点取自规则集里的一个真实条目，走的是服务器对它的匹配结果。紫色经代理，青色直连，橙色被拦截，灰色是还没被规则认出。

## 追踪一个网址

在「流向追踪」里输入域名或 IP，会列出它没命中哪些规则、命中哪一条（以及是规则集里的哪个条目）、每一层策略组怎么选，最后从哪里出去。地图上会有一个圆点沿规则逐条比对。

几种情况会标「无法判断」，因为服务器拿不到这些信息：

- 规则看应用（进程名）：在「应用与 UDP」里填写应用名就能判断。
- 规则看端口、来源地址等连接信息。
- 需要知道 IP：域名规则都没认出时，客户端会解析域名再比对 IP 规则。本站不替你查 DNS；你可以直接输入 IP 再追踪。

右上角的**常用网站体检**一次追踪三十多个常见网站，看它们各自走哪条规则。

## 修改分流

- **改走向**：把一条规则拖到另一个策略组，或拖到「直连」「拦截」上。
- **调整顺序**：拖到另一条规则的上沿或下沿。兜底规则必须在最后。
- **合并为合集**：拖到另一个规则集的中间。在详情里可以把一个成员拆出来。
- **加入成员**：把策略组或节点拖到另一个策略组上。会让策略组互相引用成环时会被拒绝，mihomo 不接受这样的配置。
- 点一行打开**详情**：不用拖动也能改走向、上下移动；策略组可以改类型（手动选择、自动选最快、故障转移、负载均衡）和参数，详情里写明了每种类型适合与不适合的场景，以及参数上的提醒。

改动先进**草稿**，下方列出改了什么。点「应用」才写入配置，之后照常自动保存和检查，也可以撤销。

第一次应用时，这个配置开始**自己管理分流**：分流规则的内容复制进配置，规则源之后的更新不再自动生效。

## 规则源更新了怎么办

自己管理分流后，规则源有变化时，分流页会提示「规则源有 N 处更新」。点「查看」逐条看变化：勾选的进入草稿，没勾选的忽略。你自己也改过的地方会标出来，默认保留你的。

## 期望

追踪完一个网址后，可以点「固定为期望」，例如「chatgpt.com 始终经过 ChatGPT 组」。之后改动分流或采纳规则源更新时，分流页的「期望」列表会标出哪些不再满足（✗），以及实际交给了谁。
